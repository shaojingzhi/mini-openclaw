- Patching LangChain tools in tests: `RequestsGetTool`, `TextRequestsWrapper`, `ShellTool`, and most other `langchain_community`/`langchain_core` tools are Pydantic-v2 models with `model_config` that forbids attribute mutation. `unittest.mock.patch("...x.y")` where `y` is an attribute on a Pydantic instance will fail at teardown with `'<Model>' object has no attribute 'y'` from the model's `__delattr__`. Workaround: patch the module-level singleton itself with a `MagicMock` (e.g. `patch("backend.tools.fetch_url._REQUESTS_TOOL", stub)`) and configure `stub.invoke.return_value = ...`. Applies to US-007 read_file tests and the US-012 mocked-LLM agent test.

- `langchain_community.tools.file_management.ReadFileTool` has built-in sandboxing via the `root_dir` field on `BaseFileToolMixin` — pass `root_dir=str(PROJECT_ROOT)` at construction and you get free `Access denied to file_path: ...` rejection for any path that resolves outside root. NO custom blacklist is needed (unlike `terminal`, where `BashProcess` has no cwd binding). The denial path covers both absolute paths (because `Path("/x") / "/etc/passwd"` returns `Path("/etc/passwd")`, which then isn't relative to root) and `..` traversal. Missing files inside root return a DIFFERENT error string (`Error: no such file or directory: ...`) — tests can rely on this distinction.

- Design notes:
  - Sessions live at `backend/sessions/{name}.json` as JSON arrays of message dicts (role + content + optional tool_calls / tool_call_id / name).
  - `load_session` returns `[]` for missing, empty, or corrupt JSON files — never raises. This matches the US-008/US-009/US-011 "graceful-empty" pattern so a single bad session file can't crash agent startup.
  - `append_message` lazily creates `SESSIONS_DIR` and the JSON file on first call (PRD criterion 4) and writes ATOMICALLY: serialize to `<file>.tmp` then `tmp.replace(path)`. A crash mid-write can't corrupt an existing session — the worst case is a stale `.tmp` left behind.
  - JSON serialization uses `ensure_ascii=False, indent=2` so Chinese / emoji content stays human-readable in the file (matters because users will read these files via the future Inspector panel).
  - `SESSIONS_DIR` is a module-level constant referenced bare inside `_session_path` so tests `patch.object(ss_mod, "SESSIONS_DIR", tmp_path)` actually take effect — per the Codebase Patterns US-008/US-011 entry.
  - Session names are validated against `^[A-Za-z0-9._-]+$` AND special-cased against `"."` / `".."` / empty. Anything else raises `ValueError` BEFORE touching the filesystem. This prevents the caller (e.g. US-014's `/api/chat` request body) from escaping `SESSIONS_DIR` via `../something` or absolute paths. The validation is intentionally stricter than necessary — a future story can loosen it if there's a real need.
  - Tests use `importlib.import_module("backend.sessions_store")` to grab the module for `patch.object`, NOT `from backend import sessions_store as ss_mod` (defensive — `backend/__init__.py` is empty today but the trick costs nothing).
- Verification:
  - `python3 -m py_compile backend/sessions_store.py backend/tests/test_sessions_store.py` → clean (host Python 3.14).
  - `/tmp/mini-openclaw-test-venv/bin/python -W ignore -m unittest backend.tests.test_sessions_store -v` → 11/11 OK in 0.003s.

- **Learnings for future iterations:**
  - For atomic JSON writes on POSIX, prefer `Path.write_text` to a `.tmp` sibling followed by `Path.replace`. `replace` is atomic on the same filesystem; do NOT cross fs boundaries (e.g. don't write the tmp file to `/tmp` and replace into the repo — that triggers a copy and loses atomicity).
  - US-014 (`POST /api/chat`) will use `sessions_store.append_message` directly. Recommended sequence per request: (1) parse body, (2) `append_message(session_id, {"role": "user", "content": message})`, (3) invoke agent, (4) on `final` event, `append_message(session_id, {"role": "assistant", "content": final_text})`. For tool calls in the middle, append a `{"role": "tool", "name": ..., "tool_call_id": ..., "content": ...}` message after each `tool_result`. The store accepts the extra fields without modification.
  - US-016 (`GET /api/sessions`) can compute `message_count` cheaply by `len(load_session(name))` — but for large directories that would re-parse every file. If perf matters, switch to `path.stat().st_size` + a 1-pass scan; for now, the simple route is fine.
  - Session-name validation regex `^[A-Za-z0-9._-]+$` lets the UI generate session IDs like `2026-06-05_main` or `session.1` without re-encoding. If a future story wants UUIDs, those already match (`hex` + dashes). Do NOT introduce slugification client-side — that would mask traversal attempts.
  - Don't read the JSON twice in append_message; we already call `load_session` (which handles missing/corrupt cases) and then write the full extended list back. That keeps the atomic-write logic in one place at the cost of one extra parse per append — acceptable given that sessions stay small (< 100 messages each in practice).
  - If a future story needs to DELETE messages or rewrite history, expose a `replace_session(name, messages)` helper rather than letting callers reach into `_session_path`. Keep the module's surface minimal: load + append are the only verbs the agent loop needs.
