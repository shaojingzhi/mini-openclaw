## Codebase Patterns
- Python backend uses Python 3.10+ syntax with `from __future__ import annotations` and PEP 604/585 typing (e.g. `dict[str, str]`).
- FastAPI app object lives in `backend/app.py` and is imported as `backend.app:app` (note: project root must be on `PYTHONPATH`, i.e. run uvicorn from repo root).
- Backend directory layout (per PRD §4): `backend/{memory,memory/logs,sessions,skills,workspace,tools,graph}` — empty dirs get `.gitkeep` so git tracks them.
- Endpoints use plain `def` returning typed dicts rather than `async def` unless I/O blocks (keep it simple until needed).
- Host Python is system Python 3.14 on macOS — it's PEP 668 "externally-managed", so any `pip install` for verification MUST use a venv (`python3 -m venv /tmp/<name>` then `<venv>/bin/pip install --dry-run -r backend/requirements.txt`). Don't use `--break-system-packages`.
- Dependencies are pinned with `==` in `backend/requirements.txt` for reproducibility. LangChain is on 1.x stable (currently 1.3.4); langchain-community 0.4.x, langchain-experimental 0.4.x, langchain-openai 1.2.x form the matching set. `langchain==1.3.4` pulls in `langchain-core 1.4.0`, `langgraph 1.2.4`, `langchain-classic 1.0.7` as transitives — all expected.
- Verify dep changes with `pip install --dry-run` in a throwaway venv; greppable signals of success: no `error`/`conflict`/`incompatible` lines, and a final `Would install ...` line.
- System Prompt source files (6 total) live in two dirs: 5 in `backend/workspace/` (SOUL/IDENTITY/USER/AGENTS/SKILLS_SNAPSHOT) and 1 in `backend/memory/` (MEMORY.md). US-011's assembler concatenates them in this fixed order: SKILLS_SNAPSHOT → SOUL → IDENTITY → USER → AGENTS → MEMORY.
- `AGENTS.md` contains TWO protocols: the SKILL PROTOCOL block must be verbatim from PRD §4.3; the MEMORY PROTOCOL block was authored locally (PRD shows it as `...`). Future stories that touch memory writes (e.g. anything appending to MEMORY.md) should respect the rules written there — read/write triggers, transparent disclosure, etc.
- When a story seeds real files into a `.gitkeep`-ed empty dir, remove the `.gitkeep` in the same commit so we don't carry placeholders forever.
- Agent tools (PRD §2.3) live in `backend/tools/<name>.py` and expose a `@tool("<name>")`-decorated function (LangChain 1.x pattern from `langchain_core.tools`). Each tool module re-exports its tool via `backend/tools/__init__.py` `__all__`. Invoke in tests with `tool.invoke({"<arg>": value})`.
- `langchain_experimental.llm_bash.bash.BashProcess` has no `cwd` parameter — to pin a shell tool to a sandbox root, prefix every command with `cd <shlex.quoted-root> && (...)` before delegating to `ShellTool().process.run(...)`. Don't reach for `subprocess` directly; the PRD §2.3 wording is "wrap" the LangChain tool.
- Tests live in `backend/tests/test_<module>.py` using stdlib `unittest` (no pytest in requirements yet). Run them in the venv with `/tmp/mini-openclaw-test-venv/bin/python -W ignore -m unittest backend.tests.test_<module> -v` — the `-W ignore` silences the noisy `langchain-community`/`langchain-experimental` "being sunset" deprecation warnings emitted at import.
- `langchain-community` and `langchain-experimental` are both formally sunset; their deprecation warnings are expected, not actionable. The PRD intentionally pins them because that's where `ShellTool`/`RequestsGetTool`/`ReadFileTool`/`PythonREPLTool` still live in the 0.4.x line we pinned in US-002.
- Tool-wrapping pattern (US-004/005/006, applies to US-007): instantiate the underlying LangChain tool ONCE at module scope as a private singleton (e.g. `_SHELL_TOOL`, `_REPL_TOOL`, `_REQUESTS_TOOL`), then expose a thin `@tool("<name>")`-decorated function whose typed signature drives the new `args_schema`. Call the singleton via `.invoke(...)` or its `.process.run(...)` for sandbox-prefixed bash. Tools normally return stdout WITH a trailing newline; `.rstrip()` is a safe normalisation (use `.splitlines()` later if line counts matter).
- Patching LangChain tools in tests: `RequestsGetTool`, `TextRequestsWrapper`, `ShellTool`, and most other `langchain_community`/`langchain_core` tools are Pydantic-v2 models with `model_config` that forbids attribute mutation. `unittest.mock.patch("...x.y")` where `y` is an attribute on a Pydantic instance will fail at teardown with `'<Model>' object has no attribute 'y'` from the model's `__delattr__`. Workaround: patch the module-level singleton itself with a `MagicMock` (e.g. `patch("backend.tools.fetch_url._REQUESTS_TOOL", stub)`) and configure `stub.invoke.return_value = ...`. Applies to US-007 read_file tests and the US-012 mocked-LLM agent test.
- `RequestsGetTool` construction requires `allow_dangerous_requests=True` — the `BaseRequestsTool.__init__` explicitly raises `ValueError` otherwise. The flag is named after the upstream LangChain security guidance, not because anything we do is more dangerous than a normal HTTP GET.
- `html2text.HTML2Text()` line-wraps to 78 cols by default, which scrambles paragraphs. Always set `converter.body_width = 0` before `.handle()` so paragraphs stay on a single line — this matters for LLM consumption.
- `langchain_community.tools.file_management.ReadFileTool` has built-in sandboxing via the `root_dir` field on `BaseFileToolMixin` — pass `root_dir=str(PROJECT_ROOT)` at construction and you get free `Access denied to file_path: ...` rejection for any path that resolves outside root. NO custom blacklist is needed (unlike `terminal`, where `BashProcess` has no cwd binding). The denial path covers both absolute paths (because `Path("/x") / "/etc/passwd"` returns `Path("/etc/passwd")`, which then isn't relative to root) and `..` traversal. Missing files inside root return a DIFFERENT error string (`Error: no such file or directory: ...`) — tests can rely on this distinction.
- LlamaIndex tools live behind LAZY imports: heavy modules from `llama_index.core` / `llama_index.retrievers.bm25` should be imported INSIDE the function that builds the index, not at module top, so `@tool` decoration and the FastAPI startup stay fast. The retriever itself is cached at module scope in a `dict` keyed by `(knowledge_dir, storage_dir)`; tests call a public `clear_cache()` between cases to force a rebuild against monkey-patched paths.
- Tests that need to monkey-patch a module attribute (`patch.object(sk_mod, "KNOWLEDGE_DIR", ...)`) MUST import the module via `importlib.import_module("backend.tools.search_knowledge_base")` — `from backend.tools import search_knowledge_base as sk_mod` will silently bind to the re-exported `@tool` function (the `__init__.py` `from … import name` rebinds the submodule attribute on the package). The same caveat applies to `read_file`, `fetch_url`, etc.
- Functions that read patched module-level state MUST refer to the names directly (e.g. `KNOWLEDGE_DIR`, not a default arg `dir = KNOWLEDGE_DIR`). Default arg values are bound at function-definition time and freeze the original `Path`; bare references go through the module globals each call and respect `patch.object`.
- LlamaIndex `QueryFusionRetriever` only calls the configured LLM when `num_queries > 1`. With `num_queries=1` it just merges results from the input retrievers via `mode` math (`reciprocal_rerank` / `simple` / `relative_score` / `dist_based_score`) — no API key needed for fusion itself. We still set `Settings.llm = MockLLM()` defensively and use `MockEmbedding(embed_dim=384)` when `OPENAI_API_KEY` is missing so `VectorStoreIndex.from_documents()` does not try to call OpenAI for embedding either.
- LlamaIndex persistence sentinel: presence of `<storage_dir>/docstore.json` means a valid index exists and can be reloaded with `StorageContext.from_defaults(persist_dir=...)` + `load_index_from_storage(ctx)`. Wrap the reload in `try/except` and fall back to a rebuild — corrupt persist dirs should never crash a tool.
- `BM25Retriever.from_defaults(nodes=...)` is the right entry point for ad-hoc indexes; it takes a list of `BaseNode` (use `list(index.docstore.docs.values())` after building a `VectorStoreIndex`). If `similarity_top_k` exceeds the corpus size, bm25s prints a warning and silently clamps to `len(nodes)` — that warning is benign.
- `backend/storage/` is ALREADY in `.gitignore` (since US-001 wave). `backend/knowledge/` is empty by design with a `.gitkeep`; the search tool gracefully reports `EMPTY_KB_MESSAGE` if the folder has no readable files or doesn't exist.
- `PyYAML 6.0.3` is a stable TRANSITIVE dep (required by langchain-core, langchain-community, langchain-classic, llama-index-core) — `import yaml` is safe anywhere in `backend/` without adding to `requirements.txt`. The same is true for other heavy transitives: check `pip show <pkg>` in `/tmp/mini-openclaw-test-venv` before deciding to pin a new direct dep that may already be present.
- YAML frontmatter parsing: use regex `r"\A---[ \t]*\n(.*?)\n---[ \t]*(?:\n|\Z)"` with `re.DOTALL` to extract the block, then `yaml.safe_load` it. Handles both newline-terminated and EOF-terminated `---` fences. Fall back to defaults (folder name, empty string) when frontmatter is missing or `yaml.safe_load` raises — never crash a bootstrap pass.
- Tests using `tempfile.TemporaryDirectory()` must keep ALL file-existence assertions INSIDE the `with` block. The tempdir is removed on `__exit__`; any `path.exists()` outside the block will return False even if the file was correctly created. (Bit me once on US-009's persistence test.)

  - `backend/tools/read_file.py` (new — `@tool("read_file")` wrapping `langchain_community.tools.file_management.ReadFileTool` with `root_dir=str(PROJECT_ROOT)`).
  - `backend/tools/__init__.py` (re-export `read_file`; `__all__` re-sorted: fetch_url, python_repl, read_file, terminal).
  - `backend/tests/test_read_file.py` (new — 4 unittest cases).
- Design notes:
  - Unlike `terminal` (US-004) where `BashProcess` had no `cwd` and we had to prefix every command with a `cd` and a destructive-command blacklist, `ReadFileTool` inherits from `BaseFileToolMixin` which already supports `root_dir`. Pass it at construction and the tool's `get_relative_path` raises `FileValidationError` for anything that resolves outside root, returning the fixed `INVALID_PATH_TEMPLATE` ("Access denied to file_path: ...").
  - `PROJECT_ROOT = Path(__file__).resolve().parents[2]` — same computation as `terminal.py`, so both tools agree on the sandbox root. If a future story needs to share this constant, expose it from `backend/tools/__init__.py`.
  - The `_READ_FILE_TOOL` singleton is a Pydantic-v2 model (same family as `RequestsGetTool`), so the no-instance-patch tip from US-006 applies if a future test needs to swap it out — but for THIS story we didn't need to mock anything, because the real filesystem provides perfectly stable inputs (`backend/app.py` always exists; `/etc/passwd` always lives outside root).
- Test coverage:
  - in-root success: reads `backend/app.py`, asserts equality with `.read_text()`.
  - absolute-path denial: `/etc/passwd` → "Access denied" string; assert NOT containing "root:" (proof the file wasn't actually read).
  - relative-traversal denial: `../../etc/passwd` → "Access denied".
  - missing-file-inside-root: distinct `no such file or directory` error (proves the denial path and the not-found path are distinguishable).
- Verification:
  - `python3 -m py_compile backend/tools/read_file.py backend/tools/__init__.py backend/tests/test_read_file.py` → clean.
  - `/tmp/mini-openclaw-test-venv/bin/python -W ignore -m unittest backend.tests.test_read_file -v` → 4/4 OK in 0.007s.
  - Full suite (`test_fetch_url` + `test_python_repl` + `test_read_file` + `test_terminal`) → 14/14 OK.
- **Learnings for future iterations:**
  - `ReadFileTool` + `WriteFileTool` (langchain_community.tools.file_management) BOTH inherit from `BaseFileToolMixin`. When US-015 implements `POST /api/files`, it can either reuse this same `_READ_FILE_TOOL` instance for reads or write a sibling `WriteFileTool` with the same `root_dir` — but watch out: US-015's allowed-roots are SUBSETS of PROJECT_ROOT (only `backend/memory`, `backend/workspace`, `backend/skills`), so the API endpoint will need a second tighter validation layer above the tool's project-root check.
  - When the tool needs to expose both a "project-root sandbox" and a "narrower allowed-roots policy" (US-015), do the narrower check FIRST in the API layer (return HTTP 403) and let the tool's own check be the safety net. Don't try to reconfigure `root_dir` per-request — Pydantic v2 models forbid the assignment.
  - On macOS, `Path("foo") / "/etc/passwd"` returns `Path("/etc/passwd")` — the right operand being absolute discards the left. That is exactly why the denial path is reached for absolute file_paths without needing a custom blacklist. Don't write a redundant `if file_path.startswith("/")` guard.
  - `INVALID_PATH_TEMPLATE` includes the literal substring `"Access denied"` — tests can assert on that substring without depending on the rest of the template wording. The miss-inside-root case uses a different substring (`"no such file"`), so test_reports_missing_file_inside_root pins both directions.

## 2026-06-04 - US-008
- Implemented the hybrid (BM25 + vector) `search_knowledge_base` agent tool.
- Files changed:
  - `backend/tools/search_knowledge_base.py` (new — `@tool("search_knowledge_base")` building a `QueryFusionRetriever` over `BM25Retriever` + `VectorIndexRetriever`; index persisted under `backend/storage/`; lazy imports + module-level retriever cache with `clear_cache()` for tests).
  - `backend/tools/__init__.py` (re-export `search_knowledge_base`; `__all__` resorted alphabetically: fetch_url, python_repl, read_file, search_knowledge_base, terminal).
  - `backend/tests/test_search_knowledge_base.py` (new — 4 unittest cases: empty dir, missing dir, seeded MD keyword retrieval, persist-to-storage check).
  - `backend/knowledge/.gitkeep` (new — seed the empty knowledge folder so layout matches PRD; `backend/storage/` was already in `.gitignore`).
- Design notes:
  - `_configure_settings()` pins `Settings.llm = MockLLM()` and, when `OPENAI_API_KEY` is absent, also `Settings.embed_model = MockEmbedding(embed_dim=384)`. Real OpenAI embeddings are picked up automatically when the env var is present.
  - `QueryFusionRetriever(num_queries=1, mode="reciprocal_rerank")` skips LLM-based query rewriting entirely — fusion is pure math over the BM25 and vector top-k node sets.
  - Persistence sentinel is `<storage_dir>/docstore.json`. Reload via `StorageContext.from_defaults(persist_dir=...)` + `load_index_from_storage(ctx)`. Reload errors fall through to a rebuild.
  - `_get_retriever()` does NOT take default-valued args; it reads `KNOWLEDGE_DIR` / `STORAGE_DIR` from module globals each call, so `patch.object(sk_mod, "KNOWLEDGE_DIR", ...)` actually takes effect.
- Test wrinkles I hit:
  - First test run crashed with `AttributeError: ... does not have the attribute 'KNOWLEDGE_DIR'` from `patch.object`. Cause: `from backend.tools import search_knowledge_base as sk_mod` resolves to the re-exported `@tool` function, NOT the module — because `backend/tools/__init__.py` did `from backend.tools.search_knowledge_base import search_knowledge_base`, which rebinds the submodule attribute on the package. Fix: `sk_mod = importlib.import_module("backend.tools.search_knowledge_base")` returns the module from `sys.modules` directly. Added Codebase Pattern about this.
  - First draft of `_get_retriever` used `def _get_retriever(knowledge_dir: Path = KNOWLEDGE_DIR, ...)` — that captures the original Path at definition time and ignores `patch.object`. Rewrote to read the module-level names directly each call.
- Verification:
  - `python3 -m py_compile` clean on all 3 new/modified files (host Python 3.14).
  - `/tmp/mini-openclaw-test-venv/bin/python -W ignore -m unittest backend.tests.test_search_knowledge_base -v` → 4/4 OK in 0.525s.
  - Full backend suite (`test_fetch_url` + `test_python_repl` + `test_read_file` + `test_search_knowledge_base` + `test_terminal`) → 18/18 OK in 0.410s.
- **Learnings for future iterations:**
  - When a future story (US-009 skills_loader, US-011 prompt_assembler, etc.) needs to monkey-patch a module attribute in tests, USE `importlib.import_module(...)` to grab the module, not `from package import submodule as alias`. The `__init__.py` re-exports shadow the submodule name.
  - Functions that should respect monkey-patched module state must reference the names directly in the body — no `def f(x=MODULE_LEVEL_PATH)` defaults.
  - `Settings` in `llama_index.core` is a global singleton; configuring it once in `_configure_settings()` is fine for our single-process tool setup, but be aware that any other LlamaIndex consumer in the same process inherits these settings (currently no others).
  - `SimpleDirectoryReader` reads MD/TXT out of the box. PDF needs `pypdf` installed — NOT in our pinned `requirements.txt`. If a future story tests PDF ingestion or production users drop PDFs into `backend/knowledge/`, add `pypdf` to requirements.txt. For now, the tool will throw at first PDF read — note this in any docs/README pass.
  - The persisted storage dir (`backend/storage/`) is gitignored. Don't commit anything into it. The `_build_or_load_index` reload path uses `docstore.json` presence as the sentinel.
  - `bm25s.BM25 requires k less than or equal to number of nodes added. Overriding ...` is a benign info-log from bm25s when corpus < top_k — not a test failure signal, just noisy. Tests should NOT assert on stderr.
  - `QueryFusionRetriever` fusion modes: `"simple"` (concat+dedupe), `"reciprocal_rerank"` (RRF, our default), `"relative_score"`, `"dist_based_score"`. RRF works well when BM25 and vector scores have wildly different scales (which they do here, especially with MockEmbedding).

## 2026-06-04 - US-009
- Implemented the Skills bootstrap that scans `backend/skills/*/SKILL.md` and emits `<available_skills>` XML.
- Files changed:
  - `backend/skills_loader.py` (new — `build_skills_snapshot(skills_dir=None, *, write=True, snapshot_path=None) -> str`).
  - `backend/tests/test_skills_loader.py` (new — 7 unittest cases).
  - `backend/workspace/SKILLS_SNAPSHOT.md` (new — seeded with the empty-wrapper output by running the bootstrap once; US-003 deliberately deferred this file to US-009).
- Design notes:
  - PyYAML is NOT pinned in `backend/requirements.txt`. It is a stable transitive of `langchain-core`, `langchain-community`, `langchain-classic`, AND `llama-index-core` (4 direct requirers), so importing `yaml` at module top is safe across the pinned dep set. Decision rationale: US-002 explicitly enumerated the 13 deps; adding PyYAML deviates from that scope, and the four transitive requirers make accidental removal extremely unlikely.
  - Frontmatter regex `r"\A---[ \t]*\n(.*?)\n---[ \t]*(?:\n|\Z)"` handles both trailing-newline AND EOF-terminated `---` blocks. `re.DOTALL` lets `.*?` cross newlines.
  - When frontmatter is missing OR `yaml.safe_load` raises, the function falls back to using the SKILL folder name as `name` and an empty string as `description`. The agent will still see the skill in the snapshot — better to surface a partially-known skill than to silently drop it.
  - `location` is hard-coded to `./backend/skills/<folder>/SKILL.md`, NOT to `skill_md.relative_to(PROJECT_ROOT)`. Reason: tests pass a temp `skills_dir` outside the project, but the production agent will always read SKILL.md via the `read_file` tool whose `root_dir=PROJECT_ROOT`. The XML must always reference the production layout regardless of where the bootstrap scanned.
  - XML escaping via `xml.sax.saxutils.escape` only handles `<`, `>`, `&` by default — quotes pass through (PRD example doesn't quote attributes; we use elements only, so quote-safety isn't required). Test `test_xml_special_chars_in_frontmatter_are_escaped` pins this contract.
  - Empty/missing skills dir returns the same empty wrapper (`<available_skills>\n</available_skills>\n`) — never crashes (consistent with US-008's `EMPTY_KB_MESSAGE` pattern).
- Test wrinkle I hit:
  - First draft of `test_write_persists_snapshot_file` ran `out.exists()` OUTSIDE the `with tempfile.TemporaryDirectory()` block, so the dir was already gone — false negative. Moved all assertions inside the `with` block. The tempdir auto-cleanup masked a real test bug for ~10s — worth remembering when writing tempdir-based tests.
- Verification:
  - `python3 -m py_compile backend/skills_loader.py backend/tests/test_skills_loader.py` → clean.
  - `/tmp/mini-openclaw-test-venv/bin/python -W ignore -m unittest backend.tests.test_skills_loader -v` → 7/7 OK in 0.004s.
  - Full backend suite (skills_loader + terminal + python_repl + fetch_url + read_file + search_knowledge_base) → 25/25 OK in 0.546s.

- **Learnings for future iterations:**
  - PyYAML is freely available via `import yaml` across the codebase — no need to add a direct pin unless the LangChain dep tree changes drastically. Same trick applies to other "obviously needed" transitives like `requests`, `httpx`, `numpy`, etc.; check with `pip show <pkg>` in the test venv before deciding to pin.
  - For functions that emit relative paths, ALWAYS write the path the production consumer expects, NOT `Path.relative_to(some_root)`. Tests that pass a fixture/temp dir should still see production-style paths in the output — that's a stronger correctness signal than "round-trip a path through the path API".
  - When writing tempdir-based tests, ALL assertions about files must be inside the `with tempfile.TemporaryDirectory() as tmp:` block. The directory (and everything inside) is gone the moment the with block exits — `out.exists()` will return False even if the file was correctly written 1 line earlier.
